# Consultar health desde el host

**Dónde:** otra terminal del host, raíz de `lab`; Next sigue activo en `lab-app`. **Antes:** servidor iniciado en puerto 3000.

```bash
curl -i http://127.0.0.1:3000/api/health
```

`curl` actúa como cliente y, sin indicar otro método, envía un GET para consultar esa ruta. `-i` muestra los encabezados de la respuesta además del body. Primero buscá el código HTTP, como `200 OK`; después del renglón vacío viene el contenido. En esta ruta es JSON, un formato de datos con claves y valores como `"status":"ok"`.

Ejemplo esperado:

```text
HTTP/1.1 200 OK
{"status":"ok","service":"nodoserrano"}
```

<img src={loopbacks} alt="Loopback del host y loopback de cada container son entornos distintos" />

Diagrama del taller; ejemplo conceptual. `localhost` siempre vuelve al entorno donde corre el cliente. En el host, esta consulta usa la publicación de Docker. Dentro de `lab-app`, `127.0.0.1:3000` apunta a Next directamente. Dentro de otro container no apunta ni al host ni a `lab-app`.

**Comprobación:** HTTP 200 y JSON del servicio `nodoserrano`. **No sigas si** hay connection refused, otra aplicación o un body distinto. Revisá Next y la publicación antes de probar el túnel.
