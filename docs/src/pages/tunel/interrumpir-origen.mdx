# Interrumpir el origen

Después de comprobar las respuestas local, interna y pública, vamos a detener el origen para observar qué cambia. Usá la terminal de consultas del host y mantené abierta la de `cloudflared`. Esta interrupción debe afectar sólo a `lab-app` de la práctica.

```bash
docker stop lab-app
curl -i https://TU_URL_PUBLICA/api/health
```

Usá el hostname actual, no el texto literal `TU_URL_PUBLICA`. La terminal que ejecutaba Next deja de servir porque detuviste su container.

La request pública ya no debería obtener una respuesta sana del origen. Es habitual ver una respuesta como esta, aunque el código puede variar:

```text
HTTP/2 502
…
```

Fijate que el túnel puede seguir conectado aunque el origen haya fallado. Comprobar que el túnel está conectado y comprobar que la app responde son dos cosas distintas. Mantener la conexión de `cloudflared` no reemplaza al servidor que acabamos de detener.

**No sigas si** detuviste otro container o todavía ves el JSON sano del servicio. Confirmá que consultás el hostname de este túnel y que su origen es `lab-app:3000`; no detengas recursos ajenos.
