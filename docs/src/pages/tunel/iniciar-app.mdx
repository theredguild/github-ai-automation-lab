# Iniciar el origen HTTP

Ahora que terminó correctamente el build actual, iniciá Next desde la shell de `lab-app`, en `/workspace`. Esta terminal va a quedar dedicada al servidor:

```bash
pnpm start --hostname 0.0.0.0
```

Dejá el proceso activo y buscá el aviso de que está listo. Esta salida es un ejemplo, no evidencia de una ejecución de la guía:

```text
Local: http://localhost:3000
Ready in …
```

`--hostname 0.0.0.0` define dónde escucha Next dentro del container. Esa dirección significa todas sus interfaces, no una URL para abrir en el navegador. Si escuchara sólo en el localhost del container, los otros containers no podrían llegar. La publicación del host sigue limitada a `127.0.0.1` por la opción de Docker.

La ruta ya provista `app/api/health/route.ts` contiene:

```typescript
export function GET() {
  return Response.json({ status: "ok", service: "nodoserrano" });
}
```

No necesitás crear otro receptor para esta consulta. Cuando Next anuncie que está listo, la terminal debe seguir ocupada por el proceso. **No sigas si** termina con error o escucha en otro puerto. Vamos a hacer las consultas en otra terminal para no interrumpirlo.
