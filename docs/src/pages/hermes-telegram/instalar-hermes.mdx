# Instalar Hermes con el instructor

Con la escritura del proyecto y del perfil comprobada sin errores, seguí junto al instructor en la shell de `lab-agent`, dentro de `/workspace` y como usuario `node`.

Vamos a instalar Hermes en vivo siguiendo la [documentación oficial de instalación](https://hermes-agent.nousresearch.com/docs/getting-started/installation). El instructor revisa sus requisitos vigentes y ejecuta ese procedimiento dentro de esta instancia, no en el host ni en el runner. El Dockerfile no incorpora silenciosamente otra instalación.

Si repetís el taller sin instructor, seguí esa misma documentación usando `node`. No copies un instalador de otra versión ni supongas que la imagen ya contiene Hermes. No necesitás estudiar sus herramientas de instalación para el resto del taller.

La imagen del taller debe incluir `libatomic1`, que necesita el Node administrado por Hermes. Si aparece un error que menciona `libatomic.so.1`, falta esa biblioteca del sistema. No es un problema del token ni del proveedor. Si ya tenés un container de una imagen anterior, seguí la [reparación de esa dependencia](/opcional/diagnostico-hermes#si-falta-libatomicso1) sin borrar tu perfil.

Cuando termine el procedimiento oficial, comprobá que el comando `hermes` esté disponible en esta shell siguiendo la comprobación de esa documentación. **No sigas si** la instalación falla o sólo quedó disponible en otro entorno. En el siguiente paso vamos a usar el wizard real de Hermes, no una implementación del taller.
