# Autorizar la operación elegida

Antes de agregar permisos, elegí cómo vas a crear el archivo y cómo iniciarás las ejecuciones. Abrí en el navegador la configuración del PAT fino de tu repositorio propio. Sólo necesitás la terminal del host si hace falta repetir el login.

En la página siguiente vas a publicar el workflow por una sola vía. La web es la opción más directa y no usa el permiso Workflows del PAT. Esta tabla te permite agregar únicamente lo que requiere tu elección:

| Operación elegida | Permiso adicional del PAT del mismo repo |
| --- | --- |
| Crear archivo desde GitHub web e iniciar desde web | Ninguno por estas operaciones |
| Iniciar y leer runs mediante CLI | Actions: Read and write |
| Enviar `.github/workflows/checks.yml` por Git | Workflows: Write |
| Registrar runner desde la web | Ningún permiso nuevo del PAT |

El PAT inicial del capítulo anterior no autoriza enviar workflows. Si elegís publicar por CLI, agregá **Workflows: Write antes del push**, no después de un rechazo. Si también vas a disparar desde CLI, agregá Actions: Read and write.

Editá los permisos en GitHub, no con `gh auth refresh`, y conservá el alcance a tu repo. **No agregues Administration ni permisos de cuenta.** Si GitHub reemplaza el token al actualizarlo, repetí [la autenticación de CLI](/proyecto/autenticar-cli) por entrada oculta en el host. Nunca pegues el token en argumentos, archivos versionados, chat o este workflow.

Comprobá en la pantalla del PAT los permisos de la operación elegida. **No sigas con el push del YAML si** elegiste Git y aún falta Workflows: Write.
