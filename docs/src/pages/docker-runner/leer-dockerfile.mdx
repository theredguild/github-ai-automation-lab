# Leer la receta real

**Dónde:** host, editor abierto en `lab/Dockerfile`. **Antes:** Docker operativo y app completa movida a `lab`.

Todo está dentro de `lab`; no traigas otro Dockerfile del material.

| Archivo dentro de lab | Para qué se usa |
| --- | --- |
| `Dockerfile` | `docker build` local para la imagen `taller` |
| `.dockerignore` | Archivos fuera del contexto de build |
| `.devcontainer/devcontainer.json` | Sólo demo opcional de Codespaces |

Abrí ese archivo, no un Dockerfile en la raíz del material ni `.devcontainer/`. Este extracto es para leer, no para reemplazar la receta:

```dockerfile
FROM node:22.23.4-bookworm-slim
RUN npm install --global pnpm@10.20.0
WORKDIR /workspace
USER node
CMD ["bash"]
```

`FROM` elige la base; `RUN` instala durante la construcción; `WORKDIR` fija la carpeta; `USER` define el usuario de ejecución; `CMD` abre Bash al iniciar la instancia. La receta usa privilegios durante la construcción para instalar paquetes y termina con `USER node`. No ejecutes las sesiones del taller como root.

| Herramienta | Uso |
| --- | --- |
| Node 22.23.4 y pnpm 10.20.0 | Aplicación y checks |
| Git y gh 2.103.3 | Git y API de GitHub |
| cloudflared 2026.10.3 | Túneles de los ejercicios 4 a 6 |
| Runner 2.338.2 | Ejecutar un job de Actions |

La receta completa instala dependencias del sistema, selecciona descargas para amd64 o arm64 y verifica sus SHA-256. Prepara `/opt/actions-runner`, `/workspace` y el home de `node`. El store de pnpm queda fuera del proyecto. No copia credenciales, no registra runners y no instala Hermes. El proyecto se montará después, en otras instancias, no en el runner.

`.devcontainer/devcontainer.json` configura la demo opcional de Codespaces con una imagen Node independiente. No participa en este build.

El Dockerfile es la receta. `docker build` la ejecuta para producir una imagen con archivos y herramientas preparados; no deja esas herramientas corriendo. `docker run` crea un container a partir de esa imagen y arranca su proceso inicial. El container tiene sus propios cambios de archivos y puede estar activo o detenido.

Reutilizaremos la misma imagen con instancias separadas para runner, agente y app. Esas instancias no comparten automáticamente sus archivos. Reconstruir la imagen no actualiza containers ya creados, aunque vuelvas a usar el nombre `taller`.
