# Explorar una instancia de herramientas

**Dónde:** host, terminal en `lab`. **Antes:** imagen `taller` construida con la elección de UID correcta.

```bash
docker run --rm -it --name herramientas taller
```

El nuevo prompt pertenece a `herramientas`. `CMD` abrió Bash y `WORKDIR` te dejó en `/workspace`. No agregues montajes ni una red propia. La conexión entre containers se introduce recién en el ejercicio 4.

Dentro del container:

```bash
whoami
pwd
node --version
pnpm --version
```

Ejemplo de salida:

```text
node
/workspace
v22.x.x
10.20.0
```

La receta fija Node 22.23.4. Desde otra terminal del host, mientras esa instancia siga abierta:

```bash
docker ps
docker exec -it herramientas bash
```

`docker exec` abre otro proceso en la misma instancia, no crea otro container. Cerrá esa segunda shell con `exit` y luego cerrá la shell inicial con `exit`. `--rm` elimina la instancia al terminar su proceso principal; la imagen permanece. En el host, `docker ps` ya no debe mostrar `herramientas`.

Docker Desktop ofrece una alternativa visual para imágenes, containers y logs. Su panel no reemplaza la shell del runner ni la consola del agente.

**No sigas si** `whoami` muestra root o las versiones no corresponden a la imagen construida.
