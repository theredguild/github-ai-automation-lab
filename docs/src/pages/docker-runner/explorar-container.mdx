# Explorar una instancia de herramientas

Con la imagen `taller` construida con la elección de UID correcta, seguí en la terminal del host, dentro de `lab`. Vamos a abrir una instancia sin montajes para reconocer qué hay dentro:

```bash
docker run --rm -it --name herramientas taller
```

El nuevo prompt pertenece a `herramientas`. `CMD` abrió Bash y `WORKDIR` te dejó en `/workspace`. No agregues montajes ni una red propia. La conexión entre containers se introduce recién en el ejercicio 4.

`-it` permite usar la terminal de forma interactiva y `--name` asigna el nombre de la instancia. Fijate que `/workspace` es una carpeta dentro del container. Llamarse igual que una carpeta del host no las conecta, así que sin un montaje no vas a ver ahí los archivos de `lab`.

En esta shell del container, comprobá usuario, carpeta y versiones:

```bash
whoami
pwd
node --version
pnpm --version
```

Ejemplo de salida:

```text
node
/workspace
v22.x.x
10.20.0
```

Compará la salida con la receta, que fija Node 22.23.4. Después, sin cerrar esta instancia, abrí otra terminal del host para verla en ejecución y entrar con una segunda shell:

```bash
docker ps
docker exec -it herramientas bash
```

`docker exec` abre otro proceso en la misma instancia activa, no crea otro container. Cerrá esa segunda shell con `exit` y luego cerrá la shell inicial con `exit`. Salir de la segunda shell no detiene la primera; salir de la inicial termina el proceso principal y, con él, el container.

`--rm` elimina la instancia al terminar ese proceso. Los archivos que hubieras creado sólo dentro de ella se pierden, pero la imagen permanece. Volvé a mirar `docker ps` en el host y comprobá que ya no muestre `herramientas`.

Docker Desktop ofrece una alternativa visual para imágenes, containers y logs. Su panel no reemplaza la shell del runner ni la consola del agente.

**No sigas si** `whoami` muestra root o las versiones no corresponden a la imagen construida.
