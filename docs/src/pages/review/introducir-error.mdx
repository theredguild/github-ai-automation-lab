# Introducir un error lógico visible

**Dónde:** host, editor y terminal en `lab`, branch `development`. **Antes:** [hook nativo configurado](/review/crear-hook), PR de tu propio repo abierto hacia `main`, no draft, sin trabajo ajeno pendiente. No hagas esta edición en la sesión del agente que revisa.

Comprobá el contexto y actualizá antes de editar:

```bash
git status
git switch development
git pull --ff-only
```

En el editor, abrí `app/capacidad.ts`. La función provista es:

```typescript
export function lugaresLibres(capacidad: number, ocupados: number): number {
  return capacidad - ocupados;
}
```

Cambiá **deliberadamente sólo la resta por suma** y guardá:

```typescript
return capacidad + ocupados;
```

Con capacidad 20 y 5 ocupados deberían quedar **15**, pero la suma devuelve **25**. Puede pasar typecheck: tener tipo correcto no implica comportamiento correcto. Es un fallo de práctica, no un cambio que deba llegar a Production.

Revisá y publicá sólo ese archivo:

```bash
git diff -- app/capacidad.ts
git add app/capacidad.ts
git commit -m "Practicar revision del calculo de lugares"
git push
gh pr list --base main --head development
```

Conservá el PR abierto. Si ya existe, el push lo actualiza. **Sólo si no hay un PR abierto de esa rama**, crealo:

```bash
gh pr create --base main --head development \
  --title "Revisar calculo de lugares libres" \
  --body "Practica de review sobre un error logico; no integrar sin corregir."
```

Reemplazá `NUMERO` por el real y anotá ambos SHA:

```bash
gh pr view NUMERO --json number,state,isDraft,baseRefName,headRefName,baseRefOid,headRefOid
gh pr view NUMERO --web
```

**Comprobación:** PR **Open**, no draft, base `main` y head `development` del mismo repo, con el commit de la suma. En la web corroborá repo de ambas ramas. El push por sí solo **no solicita review** en esta ruta, aunque la etiqueta estuviera presente.

**No sigas si** falló pull o push, hay cambios no previstos, el PR viene de un fork, apunta a otra base o sigue draft. No integres el fallo. La review analizará el diff como datos sin ejecutar código del PR.
