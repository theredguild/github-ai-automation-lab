# Conectar el agente existente a la red

Con el [health local correcto](/review/comprobar-listener), vamos a conectar el container existente `lab-agent` a `red-taller`, la red creada en el capítulo del túnel. Trabajá desde el host, en `lab`, sin cambiar de rama.

El agente se creó sin esta red y el connector necesita resolver su nombre para llegar al puerto 8644. Antes de conectar nada, mirá las redes de **tu** container:

```bash
docker inspect lab-agent --format '{{json .NetworkSettings.Networks}}'
```

- Si ya aparece `red-taller`, **no repitas la conexión**.
- Si no aparece, conectá la instancia existente una vez:

```bash
docker network connect red-taller lab-agent
```

Después de conectarlo, volvé a consultar sus redes:

```bash
docker inspect lab-agent --format '{{json .NetworkSettings.Networks}}'
```

Buscá `red-taller` en la respuesta. Al conectar la misma instancia, el perfil y la sesión `gh` permanecen en su container.

**No sigas si** la red o el container no existen, el nombre pertenece a otro recurso o Docker rechaza la conexión por otra causa. No recrees el agente ni borres redes ajenas. Una conexión ya existente se resuelve omitiendo la línea, no eliminando y creando el container.
