# Crear el hook del gateway

Ahora vamos a indicarle a GitHub dónde entregar los eventos de esta review. Podés hacerlo desde Hermes CLI en `lab-agent`, dentro de `/workspace`, o desde el navegador de tu repo. Antes de empezar, necesitás las [etiquetas preparadas](/review/crear-etiquetas), el hostname **nuevo** del túnel, la ruta nativa activa y el secret nuevo del gateway. El hook de Next debe seguir inactivo.

Elegí **una** de las formas siguientes para crear o actualizar este hook. Son alternativas para el mismo resultado, no un motivo para crear dos hooks.

## Delegar al agente

Para delegar esta operación, el PAT del agente necesita Webhooks: Read and write. Enviá este prompt sin agregar secretos:

```text
Creá o actualizá sólo el webhook de esta review en TU_USUARIO/REPO.
URL: https://TU_URL_PUBLICA/webhooks/github-pr-review
Usá el secret de Webhooks del gateway sin mostrarlo ni imprimirlo.
Content type: application/json. Sólo eventos Pull requests y TLS verificado.
No alteres hooks ajenos ni reglas del repo.
El hook anterior de /api/github debe seguir inactivo; comprobalo.
```

:::details[Alternativa web: mismo hook, sin delegar]
En **Settings → Webhooks → Add webhook**, o editando exclusivamente un hook ya identificado como el de esta review:

1. **Payload URL:** `https://TU_URL_PUBLICA/webhooks/github-pr-review`.
2. **Content type:** `application/json`.
3. **Secret:** secret nuevo de Webhooks del gateway.
4. **Let me select individual events → Pull requests**, únicamente.
5. **SSL verification** habilitado y **Active** marcado. Guardá.

No reutilices por suposición el secret del receptor Next. Ambos extremos de **este hook** deben coincidir. El secret no es el PAT de GitHub, token de Telegram ni API key del modelo.
:::

GitHub usa ese secret para firmar cada entrega y el receptor lo usa para verificarla. No lo envía como contraseña en el evento. En cambio, la sesión `gh` usa el PAT para leer el PR y publicar el comentario. Conviene distinguirlos porque permiten operaciones diferentes.

Al terminar, revisá en la web que haya un único hook de esta review, con hostname actual, path nativo, JSON, Pull requests, TLS verificado y activo. Comprobá también que `/api/github` permanezca inactivo y conserve su historial. El ping inicial sólo comprueba una entrega de inicio; no es una review ni reemplaza un `pull_request/labeled`.

**No sigas si** hay hooks duplicados, una URL vieja, un secret de otro receptor o TLS sin verificar. Corregí sólo los hooks de tu práctica; no modifiques reglas ni hooks ajenos.
