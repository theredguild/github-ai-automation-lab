# Comprobar primero el filtro negativo

Antes de pedir una review, vamos a comprobar que una etiqueta diferente no active el modelo. Necesitás el [error publicado en el PR abierto](/review/introducir-error), el hook activo y el gateway y el túnel corriendo. Tené a mano el selector **Labels** de tu PR, **Recent Deliveries** del hook nativo, la terminal del gateway en `lab-agent`, dentro de `/workspace`, y el panel de uso del proveedor. No solicites trabajo al modelo desde otra conversación durante esta observación, así podremos distinguir qué ocurrió con este evento.

Agregá **prueba-webhook** en el selector web Labels del PR. Si ya estaba, quitála y volvé a agregarla para producir un nuevo `labeled`. No uses `gh pr edit` para esta operación, porque queremos evitar consultas adicionales que pueden no estar habilitadas para el PAT fino.

Buscá esa entrega en **Settings → Webhooks → hook nativo → Recent Deliveries** y seguí el mismo evento en cada lugar:

1. Request corresponde al PR, acción `labeled` y etiqueta `prueba-webhook`. Anotá hora y GUID, el identificador de esa entrega, para ubicar el mismo evento en los logs.
2. Hostname y path son los actuales del gateway.
3. Respuesta y logs muestran que el filtro no coincide y no crea una tarea de review.
4. Contrastá logs con el uso del proveedor para comprobar que **ese evento** no inició una llamada al modelo. Considerá la hora de actualización del panel y separá cualquier actividad de otras sesiones.

Para dar esta prueba por comprobada, necesitás una entrega real que haya sido ignorada por no ser `ai-review`, antes de gastar tokens. **La ausencia de comentario no demuestra por sí sola ausencia de llamada.** Si el proveedor todavía no muestra datos, esperá esa evidencia y no presentes el resultado como demostrado.

**No sigas si** no hay entrega, no podés correlacionarla o aparece una tarea del modelo para esta etiqueta. Revisá los filtros de [la ruta](/review/configurar-ruta). Deben seguir antes del modelo, no pasar al prompt ni perder verificaciones para avanzar. Si falla el recorrido, el [diagnóstico por última evidencia](/opcional/diagnostico-review) te ayuda a ubicar el problema sin cambiar a un modelo pago.
