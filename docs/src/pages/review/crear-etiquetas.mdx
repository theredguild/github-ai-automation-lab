# Crear las etiquetas del experimento

**Dónde:** navegador de tu repo GitHub, **Issues o Pull requests → Labels**. Host en `lab` para abrir el PR si hace falta. **Antes:** [gateway accesible con hostname nuevo](/review/cambiar-tunel) y PR propio abierto `development → main`. Branch sin cambios.

Creá `ai-review` y `prueba-webhook` **si no existen**. Conservá las etiquetas existentes con esos nombres. El nombre debe coincidir exactamente con el filtro, incluida la etiqueta positiva `ai-review`.

<img src={labels} alt="Entrada al panel Labels del repositorio de GitHub para crear etiquetas" />

Captura de referencia del taller; los datos visibles no son evidencia de tu repo.

En el PR, ubicá el selector lateral **Labels** que permite agregar y quitar cada etiqueta. Todavía no agregues `ai-review`: primero probaremos el filtro negativo con el hook configurado.

Podés pedir a Hermes que cree sólo las dos etiquetas ausentes como alternativa a crearlas en la web. El permiso Pull requests del PAT alcanza para ese endpoint; no agregues Issues ni permisos de organización por reflejo. Para **solicitar** la review usaremos el selector web Labels, sin depender de consultas adicionales de `gh pr edit`.

**Comprobación:** ambas etiquetas existen y encontraste el selector del PR correcto. **No sigas si** estás en un repo ajeno o el nombre positivo no coincide con el filtro. Si `ai-review` ya está aplicada, recordá que deberá quitarse y volver a agregarse para producir un evento nuevo `labeled`.
