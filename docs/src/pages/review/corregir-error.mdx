# Corregir y comprobar el cálculo

Después de [leer críticamente la review](/review/leer-review), vamos a corregir el cálculo y comprobarlo con las herramientas del proyecto. La corrección la decide y ejecuta una persona, no el agente revisor. Usá el editor y la terminal del host, en `lab`, sobre `development`. El PR propio debe seguir abierto, y necesitás Node 22 y las dependencias del proyecto disponibles.

Antes de editar, confirmá la carpeta y la rama:

```bash
git status
git branch --show-current
```

Si no estás en `development`, no edites hasta volver de forma segura a esa rama. En `app/capacidad.ts` reemplazá la suma incorrecta por la resta y guardá:

```typescript
export function lugaresLibres(capacidad: number, ocupados: number): number {
  return capacidad - ocupados;
}
```

Desde la raíz de `lab`, revisá el cambio y corré los checks incluidos. Así vamos a contrastar la corrección con pruebas, reglas de código y tipos:

```bash
git diff -- app/capacidad.ts
pnpm test
pnpm lint
pnpm typecheck
```

Las pruebas existentes comprueban que `lugaresLibres(20, 5)` da 15 y `lugaresLibres(20, 20)` da 0, además del receptor y health. Cada aserción compara un resultado real con el esperado, así que no hace falta otro script de Node. `pnpm test` ejecuta las pruebas unitarias provistas con Node 22, no una integración de Next, Docker o servicios externos.

Biome revisa reglas del código y TypeScript comprueba tipos. Ninguno sustituye las aserciones del cálculo, por eso necesitamos los tres checks.

Para avanzar, el diff debe mostrar sólo la corrección esperada y **test, lint y typecheck deben terminar correctamente**. Guardá qué comandos ejecutaste y para qué estado del código. Esas comprobaciones las hiciste vos, no la review del agente.

**No sigas si** falla cualquiera de los tres checks, hay cambios ajenos o estás en otra rama. Corregí la causa y ejecutá los checks otra vez antes de publicar. No cambies tests para tolerar la suma ni ignores un check porque el comentario parezca convincente.
