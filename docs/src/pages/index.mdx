# De un commit a trabajo autónomo

## Sobre este taller

Este es un taller muy introductorio, diseñado por **The Red Guild** para darse inicialmente en **NodoSerrano**. Tiene un formato práctico e improvisado: vamos a probar, equivocarnos y explicar lo que aparezca durante el recorrido.

Está pensado para personas que quieren sumar herramientas y práctica para mejorar sus posibilidades al buscar trabajo. El objetivo es aprender formas de resolver tareas que aparecen en equipos de desarrollo: automatizar lo repetitivo, delegar trabajo con criterio y comprobar los resultados.

## Qué necesitás saber

Alcanza con tener algunas nociones de **Git, GitHub, programación y conceptos generales de informática**. No hace falta dominarlos: vamos a retomar y explicar los conceptos necesarios a medida que aparezcan.

Como referencia, conviene que puedas reconocer archivos y carpetas de un proyecto, leer un fragmento sencillo de código y ubicar qué son un repositorio y un commit. No hace falta memorizar comandos ni saber construir una aplicación desde cero.

No necesitás experiencia previa con automatización ni agentes.

## Qué vas a aprender

Hacer un cambio suele traer más trabajo: comprobar que todo siga funcionando, avisar y pedir una revisión. La propuesta es que esas tareas dejen de depender de que alguien se acuerde de ejecutarlas una por una.

Una automatización sigue reglas que dejamos preparadas: cuando ocurre algo, ejecuta determinados pasos. Un agente permite delegar tareas cuyo recorrido no está completamente definido de antemano, pero también puede equivocarse.

Para hablar de agentes vamos a distinguir estas piezas. Los nombres no siempre se usan igual entre productos; en este curso los usaremos así:

| Concepto | Qué significa acá |
| --- | --- |
| Modelo | Recibe contexto y genera respuestas o propone acciones. No ejecuta por sí mismo los comandos de tu computadora. |
| [Harness](https://openai.com/index/unlocking-the-codex-harness/) | Es el software que organiza la ejecución: llama al modelo, ejecuta las herramientas solicitadas, devuelve sus resultados y mantiene el contexto. También puede aplicar límites y pedir aprobaciones. |
| Agente | Es el sistema que combina esas piezas con instrucciones, herramientas y permisos para trabajar sobre un objetivo, eligiendo pasos según lo que va encontrando. |

En el taller, Hermes aporta el software que organiza ese trabajo y el modelo se configura por separado. Al conjunto preparado para recibir un pedido, leer cambios y devolver observaciones lo llamaremos nuestro agente revisor. El container será su entorno de ejecución, no el harness.

En este recorrido vas a aprender a:

- **Automatizar tareas repetitivas** y definir cuándo deben ejecutarse.
- **Conectar acciones** para que el resultado de una ponga en marcha el siguiente paso.
- **Delegarle trabajo a un agente**, dándole un objetivo concreto, contexto y permisos limitados.
- **Comprobar los resultados**, detectar fallas y decidir cuándo intervenir.

Primero vas a hacer cada parte para entender cómo funciona. Después vas a automatizarla y observar qué ocurre ante cambios y errores. Vas a distinguir qué se resuelve con reglas claras, qué requiere interpretación y qué decisiones conviene mantener en tus manos.

Al terminar, vas a tener un flujo que recibe un pedido de revisión, le permite a un agente leer los cambios y devuelve sus observaciones. Vos vas a comprobarlas, corregir lo que corresponda y decidir si integrás el cambio. En este taller, integrar el código sigue siendo una decisión y una acción humana.
