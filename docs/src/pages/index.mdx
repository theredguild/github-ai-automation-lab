# GitHub × AI Automation Lab

Construí la landing del HackerSpace de Nodo Serrano y usala para observar qué ocurre después de cada cambio. Seguí las páginas en orden con **Next**. Cada operación termina con una comprobación antes de avanzar.

El recorrido principal usa **tu equipo**, con Bash o WSL2. Docker aparece en el capítulo 2. Codespaces queda como demo opcional después de terminar el capítulo 1; no es otro camino para completar los seis ejercicios.

| Capítulo | Resultado que vas a comprobar |
| --- | --- |
| [1. Proyecto y deploy](/proyecto) | Production desde `main`, Preview desde `development` y un PR integrado |
| [2. Docker y runner](/docker-runner) | Un check pasa, falla por un error deliberado y vuelve a pasar |
| [3. Hermes y Telegram](/hermes-telegram) | Una conversación por terminal y otra desde Telegram |
| [4. El túnel](/tunel) | La misma respuesta local se consulta por una URL HTTPS pública |
| [5. El webhook](/webhook) | GitHub envía un evento firmado y el receptor responde sin IA |
| [6. La review](/review) | Una etiqueta solicita una revisión y la respuesta vuelve al PR |
| [Cierre](/cierre) | Hooks desactivados, procesos detenidos y tokens dedicados revocados |

[Empezar por los requisitos](/preparacion/requisitos).

Las capturas son referencias oficiales o públicas identificadas. Algunas muestran interfaces históricas y repos de ejemplo. Los diagramas pertenecen al material del taller; los SHA dibujados son ilustrativos. Ninguna captura o salida de ejemplo prueba tu integración: comprobá tu repo, commit, URL y respuesta reales.

Las [opciones y diagnósticos](/opcional) quedan fuera de la secuencia principal. Consultalos cuando corresponda y usá su enlace de regreso para retomar el paso.
