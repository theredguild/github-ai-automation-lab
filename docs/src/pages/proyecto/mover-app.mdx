# Mover y verificar la app

**Dónde:** host, Bash en `github-ai-automation-lab/`. **Antes:** clone correcto y un destino hermano que todavía no exista. El ejemplo usa `lab`.

No hagas `mkdir lab` antes. Revisá su ausencia en el explorador y mové la carpeta completa:

```bash
mv hackerspace-site ../lab
```

Si `lab` ya existe, `mv` puede anidar la app en vez de renombrarla. Si el destino existe o el comando falla, detenete y elegí otro nombre; no copies otra vez ni inicialices nada.

Después del movimiento correcto:

```bash
cd ../lab
pwd
```

El directorio debe terminar en `/lab`. Ejemplo de salida, no comando:

```text
/home/TU_USUARIO/proyectos/lab
```

Comprobá en el editor esta estructura:

```text
lab/
  app/
  public/
  package.json
  pnpm-lock.yaml
  Dockerfile
  .dockerignore
  .gitignore
  .devcontainer/
    devcontainer.json
```

Mover incluye archivos ocultos. La `.git` del taller quedó un nivel arriba: no hay que borrarla. El checkout del material mostrará la carpeta como eliminada; no confirmes esos cambios allí. Desde ahora trabajás sólo en `lab`; guía y presentación quedan en el material o se consultan desde GitHub.

`Dockerfile` está junto a `package.json`. `.devcontainer/` sólo configura la demo remota posterior, no reemplaza ese Dockerfile.

**No sigas si** falla `cd`, la ruta no es la app externa o faltan los archivos. No ejecutes `git init` en el material.
