# Publicar development

Con el commit del título creado y revisado, vamos a enviar `development`. Seguí en la terminal del host, dentro de `lab` y en esa rama. Después del push, los otros comandos nos van a mostrar el mensaje y el SHA de la versión enviada:

```bash
git push -u origin development
git log -1 --oneline
git rev-parse --short HEAD
```

Esperá a que el push a `development` termine correctamente. En la salida de las consultas, identificá el SHA y el mensaje que acabás de enviar. Este es un ejemplo, no son datos de tu ejecución:

```text
49a1de0 Actualiza la portada del HackerSpace
49a1de0
```

Abrí la rama `development` en GitHub y comprobá que esté ese mismo commit. El push le entrega la nueva versión a la integración Git de Vercel. Production sigue tomando `main`, así que el título nuevo todavía no debería aparecer allí.

**No sigas si** falla el push o el commit remoto no coincide. No vuelvas a clonar ni crees otro proyecto para provocar el deployment.
