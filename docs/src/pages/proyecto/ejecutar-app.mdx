# Ejecutar y reconocer la landing

El build ya terminó correctamente. Vamos a abrir la landing y reconocer qué contiene antes de cambiarla. Usá la terminal del host en `lab`, todavía en `main`, y el navegador de tu equipo. Hasta acá no usamos Docker.

`pnpm dev` ejecuta el script de desarrollo de `package.json`. Next mantiene un servidor activo y actualiza la página cuando guardás cambios. A diferencia de `pnpm build`, este comando va a seguir corriendo hasta que lo detengas.

```bash
pnpm dev
```

Dejá esa terminal abierta. Abrí `http://localhost:3000` o el puerto que indique Next. Si necesitás comandos mientras corre, abrí otra terminal en `lab`.

Buscá el título HackerSpace Nodo Serrano, las actividades y la imagen. Probá **Conocer el espacio**, revisá los enlaces de contacto y localizá el título en `app/page.tsx`. Así vas a poder reconocer el cambio cuando lo hagamos. Esta URL local no es Production de Vercel.

Estos son los archivos que vamos a ir usando durante el taller:

| Archivo | Uso en el taller |
| --- | --- |
| `app/page.tsx` | Contenido de la landing |
| `app/globals.css` | Estilos |
| `app/estado.ts` | Número tipado para provocar un error de TypeScript |
| `app/capacidad.ts` | Cálculo para practicar una review |
| `app/api/health/route.ts` | Respuesta para observar la red |
| `app/api/github/route.ts` | Receptor del ejercicio de webhook |
| `package.json` | Comandos del proyecto |
| `pnpm-lock.yaml` | Dependencias fijadas |
| `Dockerfile` | Entorno que se usará con el runner |

Cuando termines de mirar la landing, detené `pnpm dev` con `Ctrl+C` en su terminal. No hace falta cerrar el entorno.

**No sigas si** no reconocés la landing o estás viendo otro proceso/puerto.
