# Crear el pull request

Ya publicaste el cambio y comparaste Preview con Production. Ahora abrí tu repo en el navegador de GitHub para proponer que `main` reciba ese cambio. Si preferís la alternativa por CLI, usá la terminal del host en `lab`, dentro de `development`.

Un pull request o PR propone integrar cambios. En el formulario, **compare / head** es la rama que los aporta y **base** es la que los recibe. Acá la dirección es `development → main`. Crear el PR todavía no hace merge.

El PR reúne el diff, la conversación, las revisiones y los resultados de checks en GitHub. Escribí qué cambiaste y cómo lo comprobaste, por ejemplo el título esperado y la URL del Preview. Así otra persona puede revisar el resultado sin adivinar tu intención.

En **Pull requests → New pull request**, elegí **base: main** y **compare: development**. Verificá el diff, escribí título y descripción y pulsá **Create pull request**.

:::details[Alternativa por CLI]
Elegí web o CLI para crear el mismo PR; no ejecutes ambos métodos.

```bash
gh pr create --base main --head development   --title "Actualiza la portada del HackerSpace"   --body "Cambia el titulo visible de la landing."
gh pr list --state open
gh pr list --base main --head development
```

La CLI devuelve una URL como `https://github.com/TU_USUARIO/REPO/pull/NUMERO`. Es ejemplo; conservá tu URL y número reales.
:::

Antes de seguir, comprobá que el PR esté abierto, con base `main`, head `development` y el commit del título. Conservá su número, porque donde los próximos comandos dicen `NUMERO` vas a poner ese valor sin `#`.

**No sigas si** el diff propone otra dirección o contiene archivos inesperados.
