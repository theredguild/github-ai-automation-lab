# Corroborar Preview desde el PR

Con el PR del cambio de título abierto, vamos a seguir el enlace desde GitHub hasta su Preview. Dejá disponibles el PR y el proyecto Vercel en el navegador.

Buscá en el último commit el estado Vercel y el comentario del bot con **Ready**, **Visit Preview**, **Inspect** o **View deployment**. Abrí ese enlace. También podés llegar al deployment desde **Details** en los checks.

<img src={prDeployment} alt="Comentario de Vercel en un PR con estado y enlaces al Preview" />

<img src={commitStatus} alt="Estado Vercel del commit en los checks de GitHub" />

Referencias oficiales de Vercel. Son ejemplos públicos distintos, no dos mitades de nuestra ejecución.

Una vez en Vercel, compará el propietario/repo, la rama `development`, el SHA del último commit, el entorno Preview, Ready y la URL. Queremos poder seguir la relación entre **tu PR y SHA** y **tu deployment Preview, estado y URL**. Abrí la página y comprobá también el título nuevo.

Tené en cuenta que la URL de rama puede cambiar tras otro push. La URL única identifica un deployment concreto. Si no aparece el comentario del bot, consultá Deployments, porque esos comentarios pueden desactivarse sin detener los builds.

Este estado corresponde al build que hace Vercel para la app. En el siguiente capítulo vamos a crear un workflow manual de Actions, que es una ejecución distinta.

**No sigas si** el enlace corresponde a otro SHA o deployment. [Vercel para GitHub](https://vercel.com/docs/git/vercel-for-github).
