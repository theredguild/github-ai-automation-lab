# Desplegar Production desde main

Sigamos en el navegador, en la configuración del nuevo proyecto Vercel, después de importar tu repo personal. Vamos a publicar primero `main` como Production. No hace falta otro proyecto para Preview.

Antes de pulsar **Deploy**, compará la configuración con estos valores:

| Campo | Valor |
| --- | --- |
| Framework Preset | Next.js |
| Root Directory | `.`: raíz de tu repo de app, no del material ni `hackerspace-site/` |
| Install Command | Autodetección por `pnpm-lock.yaml`, sin Override |
| Build Command | `pnpm build` |
| Node.js | 22.x en la configuración disponible del proyecto |
| Production Branch | `main` |
| Environment Variables | Ninguna necesaria para esta landing |

<img src={framework} alt="Autodetección del framework en la configuración de Vercel" />

La captura es un recorte de documentación oficial de Vercel. Te ayuda a ubicar el selector, pero no demuestra un deployment del taller. Usá los valores de la tabla y no copies overrides ajenos.

Dejá Install Command en autodetección. No lo sobrescribas con un `pnpm install` genérico, porque Vercel puede seleccionar otra versión del gestor. Si necesitás fijar exactamente `pnpm@10.20.0`, se habilita Corepack según la [documentación de gestores](https://vercel.com/docs/package-managers). No hace falta en el camino básico de autodetección.

El receptor de webhooks se usará localmente después. No cargues sus secretos aquí ni en variables `NEXT_PUBLIC_*`.

Con esos valores revisados, pulsá **Deploy**, abrí **Build Logs** y seguí el build hasta que aparezca **Ready**.

<img src={logs} alt="Ubicación de Build Logs en un deployment de Vercel" />

Referencia oficial de Vercel.

**No sigas si** falla el build: leé su primer error, no sólo el último resumen. [Diagnóstico opcional](/opcional/diagnostico-vercel). Ready significa preparado; todavía falta abrir y comprobar la URL.
