# Revocar los tokens dedicados

**Dónde:** GitHub → **Settings → Developer settings → Personal access tokens → Fine-grained tokens**. **Antes:** decidiste terminar la práctica, desactivaste sus hooks y detuviste sus procesos. Si un cierre falló, no tomes ese fallo como motivo para dejar credenciales innecesarias activas; conservá qué recurso falta cerrar.

Revocá los PAT dedicados que generaste para el host y para el agente cuando dejen de ser necesarios. Comprobá sus nombres y repo seleccionado antes de actuar: no revoques credenciales de otros proyectos por rutina.

Cerrar una sesión local o detener un container no revoca un token remoto. Borrar el perfil tampoco lo revoca. A la inversa, revocar el PAT no borra los archivos guardados ni desactiva por sí solo un webhook ya creado.

No publiques el perfil de Hermes ni la configuración de `gh`; pueden conservar otras credenciales, como las del modelo y Telegram. El volumen del perfil sigue siendo privado aunque hayas revocado los PAT. Si creaste credenciales exclusivas para la práctica en otros servicios y ya no las necesitás, retiralas desde el servicio que las emitió. No revoques credenciales compartidas con otros proyectos por rutina.

El secret del webhook es una clave compartida para verificar firmas, no un PAT. Desactivar el hook no borra ese secret. Si sospechás que se expuso, reemplazalo en GitHub y en el receptor antes de volver a activar el hook; no confíes en que apagar procesos resolvió la exposición.

**Comprobación:** los tokens dedicados ya no aparecen activos en GitHub. Conservás tu repo, los resultados de la práctica y sabés qué perfiles y configuraciones siguen conteniendo secretos.

Para continuar con otro backend, mantené los filtros previos al modelo, los SHA fijados y la revisión humana. Las [referencias](/referencias) y los [diagnósticos](/opcional) quedan disponibles para consulta.
