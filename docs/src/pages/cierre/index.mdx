# Cerrar la práctica

Podés usar este cierre al terminar o **si te detenés en cualquier capítulo**, incluso antes de usar Docker o sin haber logrado la review, el merge o el deployment. Vamos a cerrar sólo lo que hayas llegado a crear, sin perder tu trabajo. Si antes querés investigar una entrega, retomá [leer la review](/review/leer-review).

El mapa reúne las partes que fuimos conectando. GitHub relaciona cambios, ejecuciones y eventos. Vercel construye deployments, el runner ejecuta checks y el túnel transporta requests. Hermes coordina la tarea y las herramientas, el modelo analiza el cambio y el adaptador publica la respuesta. La decisión de integrar sigue en manos de una persona.

<img src={systemMap} alt="Mapa del taller: GitHub conectado con Vercel, runner, túnel y agente de review" />

Este diagrama del taller muestra esas relaciones, no una ejecución certificada de nuestras cuentas.

Guardá los cambios útiles con commit y push, sin incluir secretos. No publiques cambios sin revisar sólo para terminar. Después vamos a desactivar los hooks, detener los procesos y revocar las credenciales dedicadas, en ese orden. Cada paso cumple una función distinta. Dejar de recibir eventos no detiene tareas ya iniciadas, y apagar un proceso no revoca su acceso. No borres por rutina el perfil que contiene tu progreso.

Antes de empezar, identificá qué recursos creaste y hasta dónde obtuviste evidencia. Si completaste el recorrido, conservá el repo, el PR integrado, el último SHA de `main` y el deployment de Production. Si te detuviste antes, guardá el último resultado y el error sin credenciales. En ambos casos, [empezá el cierre](/cierre/desactivar-hooks).
