# Encontrar dónde falló el deployment

Para encontrar dónde se interrumpió el deployment, abrí tu proyecto Vercel y tu repo propio en GitHub. Tené a mano el commit que intentás desplegar. Empezá por el síntoma que estás viendo y seguí la comprobación de esa fila:

| Síntoma | Primera comprobación |
| --- | --- |
| El repo no aparece | Cuenta elegida y acceso de la GitHub App al repo |
| No detecta Next.js | Root Directory es `.` en el repo de la app, no la raíz del material |
| Falla el build | Primer error de Build Logs y comandos de `package.json` |
| No ves el cambio | Rama, SHA del deployment y URL que abriste |
| No aparece Preview | Branch Tracking de Production es main; Preview recibe ramas no asignadas |
| La URL pide login | Deployment Protection, no necesariamente un build fallido |

Si el proyecto ya tenía ajustes, revisá que `git.deploymentEnabled` no excluya `development` y que **Build and Deployment → Ignored Build Step** no cancele Preview. No agregues esas opciones al camino que ya funciona.

Recordá que el entorno Vercel **Development** no es la rama Git `development`. No crees otro proyecto para lograr Preview ni desactives la protección, publiques el repo o compres un plan para ocultar un error. Los repos privados de organización pueden tener restricciones distintas de un repo personal en Hobby.

Antes de volver al recorrido, identificá qué capa falla y comprobá que conservás el repo, la rama y el SHA correctos. Podés consultar la [Configuración Git](https://vercel.com/docs/project-configuration/git-configuration).
