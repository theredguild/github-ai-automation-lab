# Referencia de túneles administrados

Esta lectura opcional te permite comparar el Quick Tunnel que ya recorrimos con una dirección administrada para otro proyecto. No necesitás terminal ni cambiar de cuenta. Es una referencia para después, no un paso para crear cuenta, registrar dominio o desplegar recursos durante el taller.

| Quick Tunnel | Túnel administrado con nombre |
| --- | --- |
| Un comando, sin cuenta ni dominio | Configuración de cuenta y connector |
| Hostname temporal del arranque | Dirección estable para el servicio |
| Adecuado para esta práctica | Requiere planificar DNS y políticas de acceso |

<img src={routing} alt="Referencia del panel de Cloudflare que agrupa túneles y muestra Hostname routes" />

La captura es una referencia pública de Cloudflare, no prueba de una cuenta o un túnel creados en el taller. [Fuente original de la captura](https://raw.githubusercontent.com/cloudflare/cloudflare-docs/production/src/assets/images/changelog/cloudflare-one/tunnel-hostname-routing.webp).

Cloudflare agrupa los túneles en su panel de red. En la captura podés reconocer **Hostname routes**, pero no hace falta reproducir esa pantalla para continuar. Para usar un hostname propio tendrías que configurar cuenta, DNS y políticas de acceso según la [documentación de túneles](https://developers.cloudflare.com/tunnel/). Tener una dirección estable no añade por sí solo autenticación al servicio ni limita qué rutas expone.

Si en otro proyecto un webhook necesita entrar sin un formulario de login interactivo, diseñá la autenticación del receptor y el acceso del emisor para que sean compatibles. **No publiques una consola privada porque el transporte use HTTPS.**

Con esta comparación alcanza para distinguir la opción administrada del método temporal que elegimos. Esta página no crea infraestructura, así que no hay recursos que comprobar o borrar.
