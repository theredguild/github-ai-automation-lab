# Desactivar sólo el hook de Next

Con la [repetición de entrega interpretada](/webhook/repetir-entrega), vamos a dejar inactivo el hook de este capítulo antes de cambiar el origen del túnel. Identificá el hook de la práctica por su ID y su path `/api/github`. Podés usar el navegador de tu repo, en **Settings → Webhooks**, o Hermes CLI dentro de `lab-agent`, en `/workspace`. No cambia la branch.

En el siguiente capítulo el destino será el gateway nativo de Hermes. Antes de crear ese hook, abrí **sólo** el que termina en `/api/github`, desmarcá **Active** y guardá. Conservá el historial de entregas, no borres el hook.

:::details[Alternativa delegada: mismo resultado]
Si elegís delegarlo, no repitas también la operación en la web. El agente necesita permiso Webhooks. Indicá el repo y el ID o URL del hook propio, nunca secretos:

```text
En TU_USUARIO/REPO desactivá exclusivamente el webhook de esta práctica que termina en /api/github.
Conservá su historial. No borres el hook ni alteres hooks de otros servicios.
Mostrame su ID, URL y estado inactivo sin credenciales.
```
:::

Comprobá en la web que ese hook aparezca inactivo y que su historial siga disponible. **No sigas si** el hook anterior sigue activo o se modificó uno ajeno. No desactives todos los hooks del repositorio por reflejo.

## Llevar el receptor a otro backend

Si después querés llevarlo a otro framework, tomá como referencia `app/api/github/route.ts`. Conservá una ruta POST pequeña y una ruta health. La validación necesita HMAC sobre los bytes originales antes de JSON, límites de body, repo y eventos, deduplicación acotada y correlación entre entrega, respuesta y logs. Podés pedir al agente que adapte el handler provisto, sin escribir uno desde cero durante la charla. Ninguna adaptación debe ejecutar código del PR.
