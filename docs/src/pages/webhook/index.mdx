# 5. El webhook

Con polling, un cliente pregunta periódicamente si hay novedades, aunque no haya cambiado nada. Con un webhook, GitHub envía una solicitud HTTP POST cuando ocurre un evento seleccionado. POST lleva los datos del aviso al receptor, a diferencia del GET que usamos para consultar health. El túnel sólo transporta esa request. El receptor valida el aviso y responde.

**Dónde:** navegador de GitHub, host en la carpeta `lab` y containers existentes `lab-agent` y `lab-app`. **Antes:** [el túnel hacia Next funciona](/tunel/recuperar-origen), tenés tu repositorio privado y conservás el perfil del agente.

En este capítulo el destino es `POST /api/github`, implementado en `app/api/github/route.ts`. No se llama a Hermes ni se ejecuta código del PR. El resultado será una entrega real `pull_request`, correlacionada con los logs, y una repetición reconocida mientras el proceso recuerde su ID. Al terminar dejarás inactivo sólo este hook para cambiar de receptor.

<img src={sequence} alt="GitHub envía un evento por el túnel al receptor y recibe una respuesta HTTP" />

Diagrama del taller; ejemplo conceptual. La respuesta HTTP confirma recepción, no una revisión de código.

| Parte del aviso | Qué identifica |
| --- | --- |
| POST + /api/github | Método y ruta del receptor |
| X-GitHub-Event | Tipo de evento, por ejemplo pull_request |
| X-GitHub-Delivery | ID de la entrega, también llamado GUID |
| X-Hub-Signature-256 | HMAC-SHA256 del body con el secret |
| Body JSON | Repositorio, acción y datos del PR |

Los encabezados, o headers, describen la solicitud; el body lleva sus datos en JSON. El evento indica qué tipo de cambio ocurrió, por ejemplo `pull_request`. La propiedad `action` del JSON precisa qué pasó dentro de ese tipo, como `opened` al abrir un PR o `synchronize` al actualizarlo con commits.

El secret compartido no va en la URL ni en código cliente. HTTPS cifra el transporte, pero no reemplaza la firma ni los filtros. El túnel expone el servicio completo de destino.

Empezá por [autenticar GitHub dentro del agente](/webhook/autenticar-agente). La sesión del host no se comparte con el container.

Referencia: [crear webhooks en GitHub](https://docs.github.com/en/webhooks/using-webhooks/creating-webhooks).
