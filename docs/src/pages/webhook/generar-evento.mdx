# Generar un evento real de PR

Vamos a provocar un evento real con un cambio visible en el proyecto. Volvé al host, a la carpeta `lab` y la branch `development`. Antes de empezar necesitás la [request sin firma rechazada con 401](/webhook/rechazar-sin-firma), un único hook activo, el túnel actual y la sesión de Git del host. Guardá cualquier trabajo pendiente antes de cambiar de branch.

Primero actualizá la rama existente, sin reset ni force-push:

```bash
git status
git switch development
git pull --ff-only
```

En el editor de `lab`, cambiá el `h1` de `app/page.tsx`, por ejemplo para presentar el HackerSpace de Nodo Serrano, o una descripción visible. Guardá el archivo antes de seguir con los comandos. Esta parte la hacés en el editor, no escribiendo un comentario en Bash.

```bash
git diff -- app/page.tsx
git add app/page.tsx
git commit -m "Presentar el HackerSpace de Nodo Serrano"
git push
gh pr list --base main --head development
```

La lista nos permite decidir si hace falta crear un PR:

- Si **ya hay un PR abierto de development hacia main**, usá ese PR. El push produce una actualización `synchronize`, así que no crees otro idéntico.
- Si **no hay un PR abierto de esa rama**, crealo con el comando siguiente y dejalo abierto:

```bash
gh pr create --base main --head development \
  --title "Presentar el HackerSpace" \
  --body "Cambio de texto para observar el webhook."
```

En ambos casos necesitamos reconocer el número y el head real del PR. Reemplazá `NUMERO` por el valor mostrado:

```bash
gh pr list --base main --head development
gh pr view NUMERO --json number,state,isDraft,baseRefName,headRefName,headRefOid
gh pr view NUMERO --web
```

Comprobá que tu PR siga abierto, vaya de `development` hacia `main` y contenga el commit recién publicado. Anotá su número y SHA head para reconocerlo después en la entrega. No lo integres todavía, porque vamos a continuar con él en la review.

**No sigas si** falló pull o push, el diff contiene secretos o cambios ajenos, o el PR apunta a otra rama o repo. Un `ping` del alta del hook no sustituye al evento `pull_request` que acabás de provocar.
