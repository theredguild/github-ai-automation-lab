# Correlacionar la entrega con los logs

Vamos a seguir el aviso desde GitHub hasta Next. Necesitás el [PR actualizado o creado](/webhook/generar-evento), su número y SHA reconocidos y el túnel todavía activo. Abrí el navegador de tu repo y dejá a la vista la terminal de `lab-app`, en `/workspace`, donde aparecen los logs de Next.

En el navegador entrá a **Settings → Webhooks → hook de /api/github → Recent Deliveries** y seleccioná la entrega `pull_request` de tu cambio. Podés inspeccionar el `ping` inicial, pero sólo prueba el alta del hook, no el evento que acabamos de provocar.

<img src={deliveries} alt="Recent Deliveries de GitHub permite abrir Request y Response de cada entrega" />

La captura es una referencia del taller. Para esta comprobación usá los datos de tu entrega real, no los de la imagen.

Seguí la entrega en este orden para no mezclar avisos distintos:

1. Fijate que la URL use el hostname actual del túnel y el path `/api/github`.
2. En **Request**, buscá `X-GitHub-Event: pull_request` y `X-GitHub-Delivery`. Anotá el GUID, la acción y el número de PR sin copiar secretos ni el body completo.
3. En **Response**, comprobá que el estado sea 200 y que el JSON indique `received` para este evento válido.
4. Buscá en Next el log `github-webhook` con el mismo delivery GUID, evento, acción, repo y número. El registro no incluye el secret ni el body completo.

El GUID y el repo nos permiten unir ambos extremos. Un 200 de otro evento o un log anterior no demuestra que haya llegado esta entrega.

| Respuesta | Interpretación en este receptor |
| --- | --- |
| 200 received | Validó y reconoció el evento; no ejecutó IA |
| 200 ignored | Evento fuera del trabajo que atiende |
| 200 duplicate | Ya recuerda ese ID de entrega |
| 401 invalid_signature | Firma faltante o inválida; revisar secret y bytes originales |
| 403 repository_not_allowed | Repo distinto al configurado |
| 404 o error del gateway | Revisar path, túnel y proceso |
| 413 body_too_large | Body supera 128 KiB |
| 415 use_application_json | Content-Type no es application/json |
| 503 receiver_not_configured | Variables faltantes o inválidas; revisar configuración y reinicio |
| 400 | Body/JSON o delivery ID inválido; inspeccionar error concreto |

Al terminar deberías poder señalar una única entrega `pull_request` y reconocer el mismo GUID al correlacionar la entrega, su respuesta y los logs. **No sigas si** sólo encontrás ping, no coincide el repo o el GUID, o necesitás eliminar firma o filtros para recibirla. Corregí la capa indicada por la respuesta, sin publicar datos privados.

Referencia: [ver entregas de GitHub](https://docs.github.com/en/webhooks/testing-and-troubleshooting-webhooks/viewing-webhook-deliveries).
